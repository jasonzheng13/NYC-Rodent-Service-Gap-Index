## Agent Memories

### Rats & Restaurants Dashboard (NYC rodent/restaurant analysis)

Dashboard ID: `01f1b3a109741fbbbb394e6da60ffdd8` — "rats and restaurants"

**Data model (5 datasets, all local metric views on `workspace.default.*` tables):**
- `restaurants` — one row per restaurant (camis = unique restaurant ID)
- `restaurant_inspections_clean` — one row per inspection violation (has `is_rodent_evidence`, `is_rat_evidence` boolean flags)
- `rodent_complaints_clean` — 311 rodent complaints (has `auto_closed`, `era`, `hours_to_close`, `open_over_30d`)
- `zip_service_gap_ranked` — per-ZIP summary with `sgi` (service gap index) and `sgi_rank`; ranked version
- `zip_service_gap_index` — per-ZIP summary without rank

**Domain conventions (user-defined):**
1. **Counting restaurants**: Use the `restaurants` table or `COUNT(DISTINCT camis)`. NEVER count rows of `restaurant_inspections_clean` as restaurant counts — that table has one row per violation, not per restaurant.
2. **Rodent evidence**: Means NYC DOHMH violation codes 04K or 04L only. The boolean column `is_rodent_evidence` already encodes this in `restaurant_inspections_clean`.
3. **"Closed without a visit" / "no-show"**: Means `auto_closed = true` in `rodent_complaints_clean`.
4. **Closure time comparisons**: Only compare closure times within the same `era` (column in `rodent_complaints_clean`). Never compare across eras directly.
5. **"Worst ZIP" ranking**: Use the `sgi` (service gap index) column from `zip_service_gap_ranked`. Always note when a ZIP has `is_sparse = true` (low data coverage — results may be unreliable).
6. **Complaint rates**: Use `complaints_capped` (from `zip_service_gap_ranked` / `zip_service_gap_index`), NOT raw `complaints`. `complaints_capped` deduplicates to one complaint per address per day.
